# GitHub 发布清单

完成下一本书的完整测试后，再执行发布。

## 发布前必须完成

- [ ] 新书能够从 Obsidian 读取书名、作者和已确认的封面来源。
- [ ] schema v3 当期目录存在 `input/intro-voice.mp3`、`input/title-voice.mp3` 和 `input/body-voiceover.mp3` 三段音频。
- [ ] 正文中文 SRT 从 `00:00:00` 开始，第一条是第一句正文且不含书名。
- [ ] 英文字幕与中文逐条对应、条数和时间一致；本期明确不用英文时已使用 `--no-english`。
- [ ] 每个分镜覆盖5～10条字幕，一镜一图。
- [ ] 片头话术、书名、正文三段音频边界连续且无重叠。
- [ ] 开场画面按快闪图片、片头 MOV、全画幅书封的优先级选择并正确承接片头话术。
- [ ] 本期实际启用的 BGM、片头 MOV、快闪图片、机械音效、水滴音效和正文开头音效可读取且时序正确；缺失的可选素材不算失败。
- [ ] 三种画幅中至少实测本期选择的画幅。
- [ ] 剪映草稿能够打开，图片、音频和字幕都有权限。
- [ ] 剪映草稿库目录由用户明确提供，未猜测或扫描私人目录；新草稿没有覆盖已有草稿。
- [ ] 封面、BGM、音效、字体和生成图片等第三方素材的许可与版权已确认。
- [ ] `npm run check` 通过。
- [ ] `npm run check:public` 通过。
- [ ] GitHub 远端是用户自己的 `readflow-studio` 仓库，不是原始参考仓库。

## 不进入 GitHub 的内容

- `.readflow.local.json`、`.env` 和本机状态。
- `episodes/` 中的书籍、音频、字幕、图片和草稿记录。
- `.tools/`、CapCut Mate 运行环境和剪映草稿。
- BGM、音效、片头 MOV、封面、生成图片等媒体文件。
- `.ai/` 和本地分析文件。
- 旧版 Whisper/HyperFrames 脚本和模板。

当前仓库来自参考项目的浅克隆。正式发布到新 GitHub 仓库时应使用干净的发布快照或清理旧历史，避免旧提交中的第三方媒体随历史一起上传。
